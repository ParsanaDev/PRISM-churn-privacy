\begin{abstract}
PRISM asks how much churn-prediction quality is lost when a model may only use less personal customer data. On the IBM Telco data we define three nested feature tiers (administrative terms; + billing; + demographics and services) and evaluate a $k$-NN baseline and a logistic regression (LR) model under one shared protocol: a stratified 80/20 hold-out split, the same five stratified CV folds, and selection by churn F-measure. Adding billing data raises test F-measure by 0.03 (LR) to 0.09 ($k$-NN); adding demographics and services adds 0.04--0.06 more. Neither model wins on every metric: LR is ahead on PR-AUC in every tier, but $k$-NN has the higher ROC-AUC and F-measure in Tier~2. LR is far more sensitive to its training settings than $k$-NN is to $k$.
\end{abstract}
\keywords{customer churn, data minimization, privacy tiers, $k$-NN, logistic regression}

\section{Introduction}
Churn models are usually trained on everything a provider knows about its customers~\cite{mozer,neslin}, while data-minimization work asks how much input a model actually needs~\cite{goldsteen}. PRISM fixes the learning protocol and varies only the information a model may see. Unlike feature selection by predictive power~\cite{omari}, each tier is fixed \emph{before} training. Milestone~3 defined the method; this report evaluates it.

\section{Research Questions}
\textbf{RQ1 (Inference performance):} \emph{How does churn classification change as a model gets access to more personal tiers, and does LR outperform the $k$-NN baseline in each tier?} This measures the cost of data minimization and whether a parametric model uses limited features better than a non-parametric one. We compare both models with their best settings on the hold-out test set (Table~\ref{tab:rq1}).

\textbf{RQ2 (Hyperparameter sensitivity):} \emph{How sensitive is each model to its hyperparameters in each tier?} A model that needs careful tuning is harder to deploy reliably. We report mean 5-fold CV F-measure over the $k$ sweep and the LR grid (Table~\ref{tab:rq2}).

\section{Dataset}
We use the public IBM Telco Customer Churn data~\cite{ibmtelco}: 7,043 customers and 33 columns, with binary label \emph{Churn Value} (1,869 churners, 26.5\%). It is a widely used churn benchmark, it is labelled, and its columns range from administrative to personal, which is exactly what our tiers need. Tier~1 has 4 attributes (tenure, contract, payment method, paperless billing), Tier~2 adds monthly and total charges (6), and Tier~3 adds demographics and subscribed services (19). Identifiers, location and outcome-derived fields (Churn Score, CLTV, Churn Reason) are never used. The only missing values are 11 blank Total Charges, all for zero-tenure customers, which we set to 0; no duplicates were found. The same cleaning applies to every model and tier.

\section{Baselines}
\textbf{$k$-NN (baseline)~\cite{coverhart}} predicts churn by majority vote of the $k$ nearest training customers under Euclidean distance. It is non-parametric, assumes no boundary shape and has one hyperparameter, so it is a transparent reference. We sweep $k\in\{1,\dots,20\}$ (scikit-learn).
\textbf{Logistic regression} scores a customer with $\sigma(\mathbf{w}^\top\mathbf{x}+b)$ and predicts churn at $\ge0.5$. Following the course notebook it minimises the absolute error $|y-\hat y|$ by mini-batch gradient descent written in NumPy. It is parametric and interpretable, a conceptually different competitor to $k$-NN. We search learning rate $\eta\in\{0.01,0.1,0.5\}$, epochs $T\in\{50,200\}$ and batch size $|B|\in\{32,128,512\}$ (18 settings). Both models receive the same inputs: numeric attributes z-scored and categorical attributes one-hot encoded, fitted on training rows only.

\section{Evaluation Strategy and Metrics}
The data is split once, stratified on churn, into a development set (5,634) and a final test set (1,409, 374 churners); 80/20 leaves enough churners in the test set for stable precision and recall. The development set is divided into five stratified folds, and every model, tier and setting uses the same folds (seed 2026). For each setting we average the fold F-measures, pick the best, refit on the whole development set and score the test set \emph{once}; the test set never influences a choice. Churn is the positive class. Because classes are imbalanced (26.5\%), we do not report accuracy. We use F-measure for selection (it balances missed churners and false alarms), precision and recall to explain it, ROC-AUC for ranking quality across thresholds, and PR-AUC, which is more informative than ROC-AUC on a minority class.

\subsection{RQ1: Performance Across Tiers}
\textbf{Effect of tiers.} Both models improve as more information is allowed (Table~\ref{tab:rq1}). Billing data (Tier~1$\to$2) is the cheapest gain for $k$-NN (F $+0.093$, ROC-AUC $+0.034$) but small for LR (F $+0.026$). Demographics and services (Tier~2$\to$3) add $+0.043$ ($k$-NN) and $+0.057$ (LR) F. So a Tier~2 model, which uses no demographic data, keeps 93\% ($k$-NN) to 91\% (LR) of the Tier~3 F-measure.

\textbf{LR vs.\ $k$-NN.} No model wins everywhere. LR has the higher PR-AUC in all three tiers, so it ranks churners better on the minority class. ROC-AUC is mixed: LR leads in Tiers~1 and~3, but by under 0.005, and $k$-NN leads in Tier~2 (0.815 vs.\ 0.807). On F-measure LR wins clearly only in Tier~1 ($+0.051$); $k$-NN wins Tier~2 ($+0.016$) and the Tier~3 gap is 0.002, i.e.\ a tie. In Tier~3 LR trades recall for precision (0.659 vs.\ 0.623).

\textbf{[Attribution: Why]} Tier~1 has a single numeric attribute (tenure), so many customers sit at identical distances and $k$-NN's vote is coarse; LR instead learns one smooth trend, and its largest weights (tenure $-8.3$, one-year contract $-7.0$) match the known pattern that new, month-to-month customers churn. In Tier~2, Total Charges is roughly tenure $\times$ Monthly Charges, an interaction a linear score cannot express but local neighbourhoods capture, which explains $k$-NN's Tier~2 lead. In Tier~3 the 40 encoded dimensions are mostly one-hot indicators, which dilute Euclidean distance; LR weights each indicator separately (e.g.\ dependents $-5.0$), giving it the higher precision and PR-AUC.

\subsection{RQ2: Hyperparameter Sensitivity}
\textbf{$k$-NN} is stable once $k\ge5$ (Table~\ref{tab:rq2}): within odd $k$ the CV F-measure varies by at most 0.045 in any tier, and the best $k$ (15, 13, 19) is moderately large. $k=1$ overfits and is 0.03--0.11 below the best. A clear zig-zag appears: even $k$ is always worse than its odd neighbours. \textbf{[Why]} With even $k$ a vote can tie at exactly 0.5, and our rule predicts churn only for a strict majority, so ties become ``no churn'' and recall drops.

\textbf{LR} is far more sensitive. Across the grid its CV F-measure spans 0 to 0.52--0.59, and 9 of 54 tier--setting pairs predict no churner at all ($F=0$). Every collapse has few or small updates ($\eta=0.01$, or $\eta=0.1$ with $|B|=512$); the selected settings all use $\eta=0.5$ and $|B|=32$, the edge of our grid. With $\eta=0.5$ fixed, the spread shrinks to 0.01--0.12. \textbf{[Why]} The absolute-error gradient $(1-2y)\hat y(1-\hat y)$ is at most 0.25 and pushes the majority (non-churn) class first, so a briefly trained model scores everyone below 0.5. Its CV ROC-AUC stays at 0.74 or higher even when $F=0$: the model already \emph{ranks} customers, but its scores have not crossed the fixed threshold. This makes LR's F-measure depend on the training budget more than on the features, and suggests extending the grid beyond $\eta=0.5$.

\section{Conclusion}
Restricting a churn model to administrative and billing data (Tier~2) retains over 90\% of the full-information F-measure, so most personal attributes add little. Neither model dominates: LR ranks minority churners better (PR-AUC) and wins on the smallest tier, while $k$-NN is competitive and much less sensitive to tuning.
